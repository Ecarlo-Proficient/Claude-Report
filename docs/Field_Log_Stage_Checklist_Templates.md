# RP Field Log — Stage Checklist Templates

> **⚠️ Superseded 2026-04-28** by `field-log-templates/` (one `.md` per stage). New canonical location: [`field-log-templates/INDEX.md`](field-log-templates/INDEX.md). This combined doc is kept for now as a single-screen overview but won't be updated when checklists change — edit the individual files in `field-log-templates/` instead.

Paste the body of each section below into its matching RP Field Log page template in Notion.

**9 contract stages, with a manual Punch Work template available.** The nine contract stages are the standard flow from Set Forms through Wreck. The Punch Work template is documented below for reference; PMs apply it manually in Notion when a builder calls back for post-completion work. There is no button for Punch Work — the auto-flip flow was removed 2026-04-27 in favor of full manual control.

**Completion is NOT a stage.** When Wreck closes, the PM flips the Bid List row's `Active Status` to `Completed`. No stage row is created for it.

**% of job complete** by stage (6 contract milestones carry %; 3 excluded — Piers, Plumb Inspect, Cable Order Date — because they aren't completion milestones or don't apply to every job):

| Stage | % Job Complete |
|---|---|
| Set Forms | 10% |
| Trench | 10% |
| Grade | 40% |
| Back Out | 10% |
| Pour Slab | 20% |
| Wreck | 10% |

**How to use this file:**
1. Open RP Field Log in Notion.
2. Click the `▾` next to `New` → **+ New template** → name it exactly as the stage heading below (e.g. `Set Forms`).
3. On the template page, set **Stage** to the matching select value (so every instance inherits it).
4. Copy the checklist body for that stage (everything under the heading, *not* including the heading itself) and paste it into the template body.
5. Save the template.
6. Repeat for all 10 templates (9 contract stages + Punch Work). The Punch Work template is created the same way but is only applied manually by PMs — no button uses it.

**Conventions used in every template:**
- To-do items (Notion `[ ]`) for concrete deliverables the super must check off.
- Sub-bullets for what "done" looks like.
- A **Photos required** section at the top calling out what photos the super must attach to the `Photos` property before this page is considered complete.
- A **Notes** section at the bottom for the super's free-text log (separate from `Quick Note` which is for one-line status).

Supers fill Start Date when they begin, End Date when they finish. Status formula auto-flips from Not Started → In Progress → Done.

## Set Forms

**Photos required** (attach to Photos property)
- Form layout before pour prep (overall site shot)
- Corner forms showing square / stake placement
- Any site conditions that deviate from plan

**Checklist**
- [ ] Plans pulled from Bid List Notes and reviewed on site
- [ ] Lot staked — corners match survey / plat
- [ ] Forms set to correct dimensions (verify against plan L × W)
- [ ] Forms leveled and squared (diagonals checked)
- [ ] Forms braced / staked for pour pressure
- [ ] Grade verified inside forms — no low spots or high spots > 1"
- [ ] Site clear of debris and drainage addressed
- [ ] Super walked the form with owner/PM if this is first pour on lot

**Notes**
- Any deviations from plan, changes requested by owner, or conditions the next stage needs to know.

## Piers

**Photos required**
- Pier hole depth (tape measure in shot)
- Rebar cage in each pier before pour
- Final piers after pour

**Checklist**
- [ ] Pier locations match plan — no offsets unless noted
- [ ] Depth meets engineer spec (record actual depth per pier if plan calls for it)
- [ ] Rebar cage centered, tied, and sized per plan
- [ ] No water or loose soil in hole at time of pour
- [ ] Concrete consolidated — no voids
- [ ] Inspector signed off if required by AHJ

**Notes**
- Any piers requiring rework, engineer call, or re-inspection.

---

## Trench

**Photos required**
- Open trench showing depth and width
- Plumbing and conduit laid in trench before backfill
- Any obstructions / relocations

**Checklist**
- [ ] Trench depth meets plan (measure at multiple points)
- [ ] Trench width adequate for plumbing + conduit + clearance
- [ ] Plumbing rough-in laid per plan
- [ ] Electrical conduit laid per plan
- [ ] Sleeves set for any pipe crossings
- [ ] No utility conflicts (gas, water, sewer) — if found, stop and call PM

**Notes**
- Record any conflicts, pipe sizes used if different from plan, AHJ inspector name if inspected.

---

## Plumb Inspect

**Photos required**
- Pressurized plumbing test gauge
- All joints visible under test
- Inspector sign-off sheet or sticker

**Checklist**
- [ ] Plumbing pressurized and holding (record PSI)
- [ ] All joints visible and uncovered for inspection
- [ ] Trades on site for inspector questions
- [ ] Inspector passed (record inspector name + time)
- [ ] Any call-backs logged and scheduled for re-inspect
- [ ] PM notified of pass/fail same day

**Notes**
- Inspection failure: what was flagged, who is fixing, re-inspect date.

## Cable Order Date

**Photos required**
- None required — this is a scheduling milestone

**Checklist**
- [ ] PT cable quantity confirmed against plan
- [ ] Cable supplier contacted with order
- [ ] Delivery date confirmed with supplier (record date)
- [ ] Delivery window communicated to site super
- [ ] PO # attached to Bid List if not already
- [ ] Cable schedule aligns with planned Grade + Pour Slab dates

**Notes**
- Supplier name, delivery date, any back-order issues.

---

## Grade

**Photos required**
- Grade inside forms before gravel / vapor barrier
- Vapor barrier installed (if applicable)
- Rebar / mesh in place ready for pour

**Checklist**
- [ ] Grade compacted to spec (95%+ compaction or per plan)
- [ ] Grade level within tolerance (string line or laser check)
- [ ] Vapor barrier installed and taped at seams (if spec)
- [ ] Rebar / mesh laid per plan — spacing verified
- [ ] Chairs / dobies in place so rebar sits at correct height
- [ ] PT cables pre-staged for layout crew (if post-tension job)
- [ ] Area clean — no debris, trash, or standing water

**Notes**
- Compaction test results, any soft spots addressed, weather concerns for pour.

---

## Back Out

**Photos required**
- PT cable layout before pour
- Anchor points and sheathing tails
- Final cable tie-offs at edges

**Checklist**
- [ ] All PT cables laid per shop drawing
- [ ] Cable spacing / drape / profile matches engineer spec
- [ ] Anchors set at edges, sheathing tails free
- [ ] No cables crossing or kinked
- [ ] Cable layout walked with PM or engineer if required
- [ ] Inspector / engineer sign-off before pour (if required)
- [ ] Pour crew briefed on cable locations before concrete arrives

**Notes**
- Engineer present? Any cables re-routed? Timing constraint for pour.

---

## Pour Slab

**Photos required**
- Concrete truck ticket (ticket # + time + mix)
- Pour in progress (wide shot + any problem areas)
- Finished slab surface before curing

**Checklist**
- [ ] Mix design matches plan (record mix ID per truck)
- [ ] Slump test passed (record number)
- [ ] Concrete placed within allowed time from batch (~90 min)
- [ ] Consolidated with vibrator — no honeycomb
- [ ] Screeded and floated per spec (trowel finish vs broom per plan)
- [ ] Control joints cut at correct spacing + timing
- [ ] Curing method applied (blankets, cure compound, water)
- [ ] Tickets collected — all given to PM / AP

**Notes**
- Weather at pour (temp, wind, rain), yardage used vs estimate, any cold joints.

---

## Wreck

**Photos required**
- Forms after strip
- Slab edges, corners, any spalling or defects
- Site clean / material returned

**Checklist**
- [ ] Forms stripped only after min cure time met
- [ ] Slab inspected for defects — edges, corners, surface
- [ ] Any defects documented with photo + location
- [ ] Forms, stakes, bracing returned to yard or next job
- [ ] PT cables stressed and cut (if post-tension, record stressing date)
- [ ] Site clean — no debris, stakes, or trash
- [ ] Final walk with PM before next trade mobilizes

**Notes**
- Stressing company + date, defects + who is repairing, next trade ETA.

## Punch Work

**When to use this template:** only when the builder calls back for post-completion work. This is not part of the default 9-stage flow. Apply manually: in RP Field Log, click the `▾` next to `New` → pick the `Punch Work` template, then fill in `Project #` and the other copy-forward fields by hand (or copy from the project's existing stage rows). The PM also flips Bid List `Active Status` from Completed → In Progress manually. Multiple Punch Work rows are allowed if separate call-backs come in over time.

**Photos required**
- Condition of punch item BEFORE work (the flaw the builder flagged)
- Work in progress / repair being performed
- Finished condition AFTER work

**Checklist**
- [ ] Punch scope confirmed in writing with builder (email, text, or site walk notes)
- [ ] Scope recorded in **Notes** below — be specific, this row may be the invoice source
- [ ] Materials / tools on site — no second trip unless scope expands
- [ ] Work completed to builder's satisfaction (walked with builder or PM)
- [ ] Photos attached showing before / during / after
- [ ] End Date filled — super's signal that the row is closed
- [ ] PM notified so `Active Status` can flip back to Completed

**Notes**
- Punch scope as requested by builder. Date builder requested. Any additional scope discovered on site. Warranty vs. paid-change-order classification (PM to confirm billing).

## Handling the "Completed" lifecycle

There is **no Completion stage**. When Wreck closes (End Date filled, all photos attached, final walk done), the PM sets the Bid List row's `Active Status` to `Completed`. That's the lifecycle signal — not a Field Log row.

If the builder later requests punch work, the PM creates a Punch Work stage row in Field Log manually using the template above and flips Bid List `Active Status` from `Completed` → `In Progress` by hand. When the punch closes, PM flips it back to `Completed`. All Active Status transitions are manual — there is no button automation for Punch Work.
